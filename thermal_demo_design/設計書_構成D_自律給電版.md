## 2. エネルギー収支分析

### LTC3108 の出力能力

| 入力条件 | TEG起電力 | LTC3108出力電力 | VLDO (2.2V) | VOUT (3.3V) |
|:---:|:---:|:---:|:---:|:---:|
| ΔT = 5℃ | ~15 mV | ~1 mW | 最大 4mA | < 0.3 mA |
| ΔT = 10℃ | ~40 mV | ~5 mW | 最大 4mA | ~1.5 mA |
| ΔT = 15℃ | ~80 mV | ~10 mW | 最大 4mA | ~3 mA |
| ΔT = 20℃ | ~120 mV | ~15 mW | 最大 4mA | ~4.5 mA |

### ESP32-C3 の消費電力

| 状態 | 電流 | 電力 | 持続時間 |
|:---:|:---:|:---:|:---:|
| Deep Sleep | 5 μA | 0.0165 mW | ~数秒〜数十秒 |
| 起床 (ADC読取) | 30 mA | 99 mW | ~10 ms |
| LEDフラッシュ中 | 30 mA | 99 mW | ~100 ms |
| 温度測定中 | 30 mA | 99 mW | ~800 ms |
| **起動時突入電流** | **~500 mA** | **~1,650 mW** | **~10 ms** |

### エネルギー収支の計算

#### 1サイクル（通常: フラッシュなし）

```
蓄電 (Deep Sleep 10秒間):
  E_charge = P_TEG × t_sleep = 10 mW × 10 s = 100 mJ  (ΔT=15℃)

消費 (起床 10ms):
  E_wake = 99 mW × 0.01 s = 0.99 mJ

Deep Sleep中の消費:
  E_sleep = 0.0165 mW × 10 s = 0.165 mJ

収支: 100 - 0.99 - 0.165 = +98.8 mJ ← 大幅な余裕 ✅
```

#### 1サイクル（LEDフラッシュあり）

```
蓄電 (10秒): 100 mJ

消費 (起床 10ms + フラッシュ 100ms):
  E_active = 99 mW × 0.11 s = 10.9 mJ

収支: 100 - 10.9 - 0.165 = +88.9 mJ ← 余裕あり ✅
```

#### 1サイクル（温度測定あり: 15サイクルに1回）

```
蓄電 (10秒): 100 mJ

消費 (起床 10ms + 温度 800ms):
  E_active = 99 mW × 0.81 s = 80.2 mJ

収支: 100 - 80.2 - 0.165 = +19.6 mJ ← ギリギリだが正 ✅
```

> **重要**: スリープ間隔を 2秒→10秒 に延ばせば、ΔT=15℃でも
> 全サイクルで収支が正になり、自律給電が成立する。

## 3. 2つのボトルネックと解決策

### ボトルネック①: 突入電流問題

ESP32-C3 の起動時に ~500 mA の突入電流が流れる。
LTC3108 の VOUT は連続 ~4.5 mA しか供給できない。

```
問題:
  ESP32起動時   : 500 mA × 10 ms = 5 mJ の瞬間エネルギー
  LTC3108の瞬間供給: 4.5 mA × 3.3V × 10 ms = 0.15 mJ
  → 差分: 4.85 mJ をキャパシタから供給する必要がある

解決策: スーパーキャパシタをバッファとして使用
  E = 0.5 × C × (V1² - V2²)
  5 mJ = 0.5 × C × (3.3² - 3.0²)  ← 電圧降下を0.3Vに制限
  C = 5 / (0.5 × 1.89) = 5.3 F

  → 10F のスーパーキャパシタで十分な余裕
```

### ボトルネック②: コールドスタート問題

電源投入時（TEGが冷えている状態から開始）、
スーパーキャパシタが空の状態からESP32を起動できる電圧まで
充電する必要がある。

```
充電時間の推定:
  必要電荷: Q = C × V = 10F × 3.3V = 33 クーロン
  LTC3108 の平均充電電流 (ΔT=15℃): ~3 mA

  充電時間 ≈ Q / I = 33 / 0.003 = 11,000 秒 ≈ 3 時間

  → 10F の場合、初回起動に約3時間かかる（非実用的）

対策:
  ① 小容量キャパシタ (0.47F) + LDOの組み合わせ
     充電時間 ≈ 0.47 × 3.3 / 0.003 ≈ 517 秒 ≈ 8.6 分
     起動後はDeep Sleepのおかげで持続可能

  ② PGD (Power Good) 信号でESP32の電源を制御
     VOUT が安定するまでESP32を OFF に保持
     → 最初の充電エネルギーを無駄にしない
```

## 5. ファームウェアの変更点

構成D のファームウェアに対して、以下の変更が必要:

### a) スリープ間隔の延長

```cpp
// 構成D (USB給電): 2秒
const uint64_t WAKE_INTERVAL_US = 2000000ULL;

// 構成D' (自律給電): 10秒 ← TEGの充電時間を確保
const uint64_t WAKE_INTERVAL_US = 10000000ULL;
```

### b) 電圧監視による適応的スリープ

```cpp
// VSTORE電圧に基づくスリープ間隔の動的調整
// エネルギーが少ない時は長く寝て、多い時は短く起きる
uint64_t calcAdaptiveSleep(float V_store) {
    if (V_store > 4.0) {
        return 5000000ULL;   // 5秒: エネルギー余裕あり → 頻繁に起床
    } else if (V_store > 3.5) {
        return 10000000ULL;  // 10秒: 標準
    } else if (V_store > 3.0) {
        return 30000000ULL;  // 30秒: エネルギー不足 → 節約モード
    } else {
        return 60000000ULL;  // 60秒: 危険 → 省エネ最優先
    }
}
```

### c) ブラウンアウト対策

```cpp
void setup() {
    // 起動直後に電圧チェック
    float V_supply = readVoltage(VSTORE_PIN);
    if (V_supply < 3.0) {
        // 電圧不足 → 何もせず即座にDeep Sleep
        esp_sleep_enable_timer_wakeup(60000000ULL); // 60秒寝る
        esp_deep_sleep_start();
    }
    // ... 通常の処理 ...
}
```

### d) 温度センサーの電源管理

```cpp
// DS18B20をVLDO (2.2V) から給電
// 測定時のみGPIOで電源ON → 読取り → 電源OFF
// これでDeep Sleep中のセンサー待機電流を完全カット
#define SENSOR_POWER_PIN 5  // GPIOでDS18B20の電源を制御

void readTemperatureOptimized() {

    delay(50);  // 安定待ち
    sensors.begin();
    sensors.requestTemperatures();
    // ... 読取り ...
    digitalWrite(SENSOR_POWER_PIN, LOW);   // 電源OFF
}
```
